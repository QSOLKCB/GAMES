# PIXEL WARFRONT: Deterministic Command

**PIXEL WARFRONT** is an original, offline browser real-time strategy game. Build
a command grid, harvest flux, produce a combined-arms force, and destroy the
hostile command node across an unbounded sequence of procedural missions.

Open [`index.html`](index.html) directly in a modern desktop browser. No server,
installation, account, network connection, asset download, telemetry, or browser
storage is required.

## What the game does

- Generates terrain, flux fields, biome identity, enemy bases, and rank pressure
  from a 32-bit campaign seed.
- Advances to a newly derived battlefield after every victory.
- Raises enemy health, damage, income, starting force, reinforcement cadence, and
  attack frequency with every mission.
- Supports box selection, formation movement, target attacks, resource orders,
  production queues, construction placement, power, and supply.
- Includes three commandable unit roles: harvesting drones, ranged infantry, and
  siege crawlers.
- Includes command nodes, grid relays, refineries, forge arrays, and defensive arc
  turrets.
- Runs authoritative gameplay at a fixed 20 ticks per second using integer world
  coordinates and deterministic target selection.
- Records only the seed and timestamped player commands. Replays contain no
  serialized battlefield, checkpoint, screenshot, or save-state snapshot.
- Draws every unit, building, battlefield tile, projectile, health bar, impact,
  and explosion procedurally on Canvas 2D.
- Synthesizes all interface, weapon, production, and ambient sounds at runtime
  through the Web Audio API.

## Controls

| Action | Control |
|---|---|
| Select a unit | Left-click |
| Add or remove from selection | `Shift` + left-click |
| Box-select units | Left-click and drag |
| Context command | Right-click terrain, enemy, or flux field |
| Move mode | `M` |
| Attack mode | `A` |
| Gather mode | `G` |
| Stop | `S` |
| Cancel mode / placement | `Escape` |
| Pause | `P` |

Production and construction are also available from the command rail. A drone
must be selected before a structure can be placed.

## Economy and command grid

Flux is the only spendable resource. Drones mine a finite field, carry flux to a
command node or completed refinery, deposit it, and return to the same field until
it is depleted.

Completed structures contribute to two constraints:

- **Supply** is provided by command nodes and grid relays. Units and queued units
  consume it.
- **Power** is generated by command nodes and relays. Refineries, forges, and
  turrets consume it. An underpowered grid suspends production and turrets until
  capacity again meets demand.

## Seeds and command replays

A seed reproduces procedural content, not player decisions. The command replay
adds only the commands issued at particular simulation ticks:

```text
PWR1.<8-hex checksum>.<base64url payload>
```

The payload is `[engineVersion, seed, tickCount, commandEntries]`. A command entry
is `[tick, commands]`; empty ticks are omitted. Playback creates a fresh mission
from the seed and applies those commands at the recorded ticks.

The checksum detects accidental damage or editing before simulation. It is not a
cryptographic signature. Recordings seal cleanly at whichever comes first: six
hours or the decoder's 16,000,000-character code ceiling. Live play can continue,
and every code emitted before the recorder seals remains loadable.

See [`docs/DETERMINISM.md`](docs/DETERMINISM.md) for the normative contract.

## Architecture

| File | Responsibility |
|---|---|
| [`core.js`](core.js) | Procedural mission generation, economy, AI, combat, fixed-tick simulation, replay codec, and state digest |
| [`app.js`](app.js) | Selection and command controls, Canvas renderer, synthesized audio, replay UI, and frame scheduling |
| [`index.html`](index.html) | Offline application shell and accessible command surface |
| [`style.css`](style.css) | Responsive industrial strategy interface |
| [`tests/core.test.js`](tests/core.test.js) | Determinism, progression, harvesting, construction, production, combat, and replay regressions |
| [`tests/offline.test.js`](tests/offline.test.js) | Offline boundary and application-shell checks |
| [`tests/browser-smoke.js`](tests/browser-smoke.js) | Real-browser launch, selection, commands, production, replay export, playback, and mobile-layout smoke test |
